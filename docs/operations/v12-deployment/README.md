## 1. 接手状态和建设顺序

截至 11 月 18 日的核对，生产 FastAPI、Redis、R-Nacos 已运行，后端在 Alembic 0022，仓库迁移头为 0023。应用连接 prod_db，实际 PostgreSQL 版本为 18.3。RDS 托管备节点、可用区和最新可恢复时间需在控制台复核。api.touhou.vote 当时无公网 DNS 记录，结果前端的 /res-be/graphql POST 返回 405。发布前复测这几项，再以新结果更新此节和常驻架构图。

| 顺序 | 负责人角色 | 交付和完成条件 |
| --- | --- | --- |
| 1. 生产入口和数据库恢复基线 | 发布、域名、DBA | 冻结发布版本并留存上一稳定版本。配置 API HTTPS；两站访问同一 prod_db。确认 RDS 系列、日志备份与可恢复窗口，在独立实例完成 PITR 并记录实测 RTO/RPO。 |
| 2. 阿里云备机房 | 云运维、后端 | ALB + ECS 伸缩组和生产依赖就绪；达到压测确定的热备容量，主机和依赖隔离得到验证。 |
| 3. 独立监控与告警 | 值班、云运维 | 生产两个站点及用户入口常驻监控，通知主备渠道实测，测试机网络隔离验证通过。 |
| 4. 自动切流和故障演练 | 值班、后端、域名、DBA | 实装就绪探测和单一切换控制器。按故障演练矩阵走完，从探测到送达均有日志。 |
| 5. 上线与交接签收 | 发布、前端、值班 | 按操作手册部署正式候选、验收双前端代理、开放导航。记录真实值班人、系统归属、RTO/RPO、回切授权人和演练证据地址。 |

## 2. 备份机房建设

1. **云运维**确定地域、可用区、VPC 和容量配额。用阿里云 ALB 对接 ECS 弹性伸缩组。先做跨可用区部署和容量评估，验证每个可用区到生产 RDS、镜像仓库及外部身份服务的链路。生产 API 域名固定由 Cloudflare LB 接入，主池为现有生产 HTTPS 网关，备池为阿里云 ALB HTTPS 源站。两站分别验收 TLS、Host 和真实客户端 IP 转发。 [阿里云 ALB 与伸缩组](https://www.alibabacloud.com/help/en/slb/application-load-balancer/use-a-scaling-group-to-scale-an-alb-instance)
2. **后端**制作可替换节点。启动模板固定 GHCR 后端 manifest digest、配置版本和健康探测。生产 JWT 与 DEK 经受控配置或密钥服务分发，校验密钥标识及解密，用同一届次和业务窗口配置。缩扩容节点只启动应用，schema 迁移由生产发布 job 单次执行。新实例空机启动、就绪登记、排空和释放都要实测。
3. **云运维与后端**保障生产状态依赖。备池使用同一个 RDS 写入 endpoint，备池 Redis、Nacos 或等效配置源应能在主站整机下线时使用。明确验证码、OAuth 临时态与限流在两站的连续性。若采用站点独立 Redis，在演练中验证未完成验证码流程的补救表现及切换期间的限流策略。
4. **云运维与 DBA**用登录、搜索、问卷、投票和结果查询的混合压测确定最小热备容量与最大副本数。最小值覆盖切换初段。主备重叠期间，以实例数 × 每实例进程数 × 每进程连接池上限估算连接预算，同时给运维和数据库内部连接留余量。确认扩容耗时、扩容失败告警以及何时暂停写入进入维护。
5. **DBA**独立验收 RDS HA 和 PITR。确认 PostgreSQL 版本与地域能购买或迁移到选定规格。在测试库或恢复副本验证切换后的连接池重连、schema、关键记录和应用回读。应用备池有独立承载能力，但两站仍依赖同一个数据库写入入口。[RDS 主备切换](https://www.alibabacloud.com/help/en/rds/apsaradb-rds-for-postgresql/switch-workloads-over-between-primary-and-secondary-apsaradb-rds-for-postgresql-instances)

## 3. 主备监控放在哪里

**主、备生产服务器由独立的生产监控持续覆盖。测试服务器保留测试环境职责，可从上线前开始提供辅助公网探测。**

| 部署位置 | 职责 |
| --- | --- |
| 生产主站及备池节点 | 每台运行指标和日志采集组件，带环境、机房和实例标签；采集 CPU、内存、磁盘、容器重启、HTTP/GraphQL 错误率、延迟与登录/提交成功率。扩容时完成采集注册，缩容时摘除实例。 |
| 独立监控服务 | 跨站接收指标；从多个网络探测主备源站就绪和两个正式前端的同源 API。分别收集 RDS 连接/复制、Redis、Nacos、ALB 健康目标数与 ESS 扩容状态。监测采集停止、探针失联及告警通道异常。 |
| 独立切换控制器 | 根据探测结果和最小容量决定路由，记录事件并提供只读状态。运行位置不依赖主备 ECS 或测试机；配置单写者锁、最小权限和受控人工接管。 |
| 测试服务器 | 辅助探测公开 HTTPS 和只读 GraphQL。访问限于对外入口，生产内网采集、写入、切流权限与生产凭据由生产体系管理。 |
| 值班通知 | Cloudflare 或云监控事件和控制器事件进入值班群，关键故障另送短信或邮件。人工可查单次事故的探测样本、主备状态、当前路由、验收结果和时间。 |

用同一个事件 ID 合并重复通知。事故首次检测、开始切流、切流成功/失败、备池故障或扩容失败、进入维护和回切完成均发送通知。发布前用实际值班联系人测试送达。[Cloudflare 监视器](https://developers.cloudflare.com/load-balancing/monitors/create-monitor/) · [阿里云告警事件与回调](https://www.alibabacloud.com/help/en/cms/cloudmonitor-1-0/user-guide/configure-callbacks-for-system-event-triggered-alerts-recommended)

## 4. 自动切流实施清单

- [ ] **就绪检测。** 应用或源站对外提供 /readyz。检查当前发布版本能服务、必需依赖可用、接入正确的生产数据库和 schema；正常返回 200，失败返回 503。现有 /health 可返回 HTTP 200 且 db_status=unavailable，探测程序若过渡使用它，必须解析响应。实例存活检查和全站就绪分开，避免共享 RDS 故障触发整组替换。
- [ ] **判定与执行。** 主池连续失败、多观测点确认，且备池 /readyz 与健康实例数达门槛后，控制器从主池切到备池。改路由前后读回当前池，持久化事故 ID 和状态；重复事件复用原操作，检测网络局部故障时继续观测并报警。
- [ ] **保护共享依赖。** 共享 RDS 故障或两池均不可服务时，路由进入独立维护端点并返回 503，暂停写入；现网 API 故障演练需覆盖已打开页面和在途请求。数据库可能发生错误时由 DBA 核实唯一写主和业务回读，独立灾备库提升、强制回切或覆盖恢复按 [操作手册](cutover-runbook.md#5-有故障时的接管步骤)执行。
- [ ] **接管验收。** 公布当前服务池后复跑两个正式域名的同源 API 与只读业务探针，并核对活动来源。写入回读使用经授权的验证数据。切流配置失败、业务探针失败或容量不足时报警并根据可用状态进入维护，由值班人接管。状态不明的写请求先回读确认结果。
- [ ] **保持接管与回切。** 上线首轮采用自动接管、验收后确认回切。控制器持久化当前业务池，使主站零星恢复探测成功时仍保持备池承载。Cloudflare 原生优先级故障转移会在主池恢复后自动回切；按图实施时由控制器管理当前服务池，预置返回 503 的独立 fallback，并验证双池异常的实际路由。主站通过稳定窗口后，按授权回切并排空备池。[Cloudflare 默认回切行为](https://developers.cloudflare.com/load-balancing/understand-basics/traffic-steering/steering-policies/standard-options/) · [全池失效时的 fallback](https://developers.cloudflare.com/load-balancing/load-balancers/common-configurations/)

阈值由故障演练确定。记录探测周期、连续成功/失败次数、多观测点要求、备池健康实例门槛、路由切换时限、回切稳定窗口和告警时限。实施交接中放监控看板、部署配置及演练记录的受控链接。

## 5. 故障演练与验收

先在隔离演练环境验证。上线前在批准的生产窗口用实际源站、通知渠道和经授权的验证账号复演关键路径。每次记录注入时刻、检测时刻、路由读回时刻、首个成功请求／回读、告警到达和回切时刻；数据库场景另记可证实的最后有效提交点。

| 场景 | 预期自动动作 | 验收证据 |
| --- | --- | --- |
| 主站断网或停止服务，备池健康 | 触发备池接管并通知，两个正式前端继续通过原 API 域名服务 | 路由读回、GraphQL JSON、登录与写入回读、未完成请求处理结果 |
| 单观测点抖动，其他观测点健康 | 记录异常并继续观测，路由维持主站 | 探测明细、无误切 |
| 备池部分实例故障或扩容失败 | 容量门槛不足时禁止接管；已有流量时按可用性降级并报警 | ALB 健康目标、ESS 活动、通知送达 |
| 主备共用 RDS 不可用 | 暂停写入，维护端点返回 503，分别报告数据库与用户入口故障 | 双站就绪失败、维护响应、无丢失或重复确认的写入 |
| 主站恢复但反复抖动 | 备池持续承载。完成稳定窗口验收后按授权回切 | 持久状态、无来回切换、主站回读与备池排空 |
| 控制器重启、事件重放、通知渠道失联 | 恢复已有事故状态，重复事件不重复改路由；备用通知路径送达 | 状态记录、变更审计、告警记录 |
| PITR 到独立实例 | 恢复并校验，可确认时点和数据差异形成记录 | 恢复时间、备份时间点、关键数据校验、实测 RTO/RPO |
