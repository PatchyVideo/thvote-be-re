# 问卷定义检查

2026-11-09，独立命令行检查器，本地实现；不新增管理台页面、接口或业务模块。

在后端仓库根目录，使用项目 Python 执行：

```bash
python -m scripts.check_questionnaire
```

手动检查与发布前使用同一命令。发布人员确认目标数据库配置后先运行检查，仅在退出码为0时继续发布。本轮没有自动接入CI、部署或后台保存流程，不会阻止编辑中的半成品被暂存。

## 数据来源与只读范围

数据库连接沿用 `get_settings().database.build_url()`，与应用配置一致（环境变量、既有配置文件及启用时的Nacos配置）；命令不接受连接串参数、不输出密码或连接串。连接信息应由运行环境提供，确认目标库后再运行，不能用本地静态TS表替代真实定义。

脚本批量读取 questionnaire_def、question_group_def、question_def、option_def 全部记录，保留普通结构加载器会过滤的孤立行。只执行查询，不调用建表、迁移、更新、提交答案、统计重算或缓存失效；用户答案不在检查范围。数据库不可达、表缺失等情况返回执行失败，不视为通过。

## 输出和退出码

示例（ID仅作演示）：

```text
[ERROR] ORPHAN_GROUP group=30: 父节点 questionnaire_id=999 不存在
[WARNING] MISSING_CODE question=100: 缺少语义 code，相关结果查询可能不可用
检查完成：1 个错误，1 个警告。
```

| 退出码 | 含义 | 发布前处理 |
|---|---|---|
| 0 | 无错误，允许存在警告 | 可继续；人工核对警告 |
| 1 | 定义存在错误，列出全部问题 | 修正定义后重跑 |
| 2 | 配置、数据库或检查执行失败 | 查看异常类别，核对运行配置、数据库连接和表结构后重跑 |

失败输出不包含原始数据库异常详情，避免连接信息泄漏。配置加载期间的内部日志也不直接输出，既有配置回退行为保持不变；检查前仍需确认目标数据库配置。

## 覆盖的规则

- ID/key重复、空key、父节点缺失；category仅main/extra；至少存在一份必填与一份extra非必填，不硬编码业务A/B/C/D的ID或数量。
- 问卷必须有题组，题组必须有题目；题组order为正整数、同问卷内唯一；唯一order=1首组默认可见且仅一道题。
- 题型仅Single/Multiple/Input，选择题有选项；Input不配选项，最大长度为正整数；选项内容非空、option_group为非负整数。
- related/mutex必须是整数ID列表，目标存在且在同问卷；related按题组order严格向后，不能指向自身组或前面的组；mutex不能指向自身。单向互斥与多选不同选项组允许存在。
- 复用现有code格式规范，非空题code为5位数字、选项code为7位，同类不重复。缺少code只警告，不要求内部ID符合语义编号格式。

## 能力边界和回滚

这是静态结构检查，不枚举用户答案、不证明所有分支可达或整套答案必定有解，不检查真实账号/问卷作答或跨届解释，也不检查结果快照是否已经重算。缺code警告可能仍影响结果查询，应按实际题目用途处理；退出0不能替代填写和结果验收。

后台保存与导入目前仅有原先的局部校验，未接本脚本的全量检查。删除脚本即可回退，无数据迁移或回滚操作。真实库检查和部署状态以实际执行记录为准。
