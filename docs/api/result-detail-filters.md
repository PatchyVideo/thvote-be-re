# 详情页投票人群筛选

状态：已实现，2026-10-22；未发布或对真实数据执行操作。

角色、音乐、组合详情的问卷统计使用 `(原筛选条件) AND 当前目标`。原条件含 OR 时保留括号，避免扩大统计人群。详情顶部票数/趋势继续使用原筛选后的对象结果，问卷区域在同一人群中进一步限定投过当前对象的人。

## 条件格式

- 角色：`(q11011=1101102) AND chars:["博丽灵梦"]`
- 音乐：`(q11011=1101102) AND musics:["信仰是为了虚幻之人"]`
- 组合：`(q11011=1101102) AND cp=("博丽灵梦","雾雨魔理沙")`
- 没有原筛选时只发送目标条件。

名称按 JSON 字符串转义。前端仍使用原有压缩 URL `q` 参数；旧图形模式约束继续可读，新链接也能保存指令模式 DSL。三个本届榜单将当前有效的图形/指令模式条件传给详情页；详情到理由页继续保留原筛选。不把关键词、最小/最大得票数等“结果行过滤”当作投票者约束。

## 组合条件

在现有 `query` DSL 内新增 `cp=("成员A","成员B"[,"成员C"])`，不新增 GraphQL 字段或 REST 端点。

- 必须恰好两人或三人；完整组合匹配，成员顺序不影响匹配与缓存指纹。
- 保留重复成员：A×A 不等于 A×B；两人组合不匹配包含同样两人的三人组合。
- 不要求指定主动方，也不限定本命；这些不属于本次详情目标条件。
- 名称与日文名复用角色白名单解析；未知名称沿用 `ADVANCED_SEARCH_UNKNOWN_NAME`，语法错误沿用 `ADVANCED_SEARCH_SYNTAX_ERROR`。
- 匹配来自有效组合提交的成员，角色部门同时投 A 和 B 不代表投了 A×B。
- 可与既有问卷/角色/音乐条件通过 AND、OR、括号组合；原有限频、缓存和复杂度限制不变。

组合成员使用 canonical candidate ID 归一后匹配，兼容已有 old_id 投票格式。DAO 最新提交与作废过滤语义不变。

## 发布与回滚

先发布支持 cp 条件的后端，再发布前端。无数据库迁移、配置或依赖变化；不触发自动计票，不清理已有结果。筛选结果仍复用现有高级搜索按需计算流程。回滚后端前应先回滚使用 cp 条件的前端。
