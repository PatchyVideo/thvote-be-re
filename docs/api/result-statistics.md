# 结果统计：有效票与问卷完成情况

状态：已实现，2026-10-22；未发布、未重算线上结果。

## 部门有效票

角色、音乐及组合排名返回的 `global.total_votes`（GraphQL `global.totalVotes`）表示部门有效提交数，不再表示候选得票之和。

沿用现有 ComputeDAO 口径：每个 vote_id 取最新提交，最新行被作废则排除，不退回旧行。一个有效提交含多个候选/组合票位，仍只计一张票。组合仅得一票时不展示该组合，但该提交仍计入部门有效票。

例如三张角色票分别选 A+B、A+B、A：部门有效票为 3，A 得票 3、B 得票 2。候选得票合计 5 不作为部门有效票。

本次不修改单候选票数、本命、平均和中位得票计算；平均得票仍基于候选得票总和计算，不因为 global.totalVotes 单位修正而改成“提交数/候选数”。不扩大有效性审查规则，也不调整候选总数统计。

## 问卷填写情况

`queryCompletionRates(voteYear, query)`、旧 GraphQL `completionRates` 及 REST `/api/v1/result/completion-rates/` 沿用现有响应形状：

```json
{
  "name": "main_required",
  "numComplete": 120,
  "total": 150,
  "rate": 0.8
}
```

上例为 GraphQL item；REST 的字典键及字段沿用 snake_case。`name` 现在是 `QuestionnaireDef.key`，不再输出 character/music/cp/questionnaire 四种部门类别。

- 根据数据库真实问卷结构逐份统计，包括选填问卷；不依赖题目/选项是否填有语义 code。
- 按 vote_year 读取答案，每位作答者只看最新 attempt 批次；旧批次中完成而新批次遗漏的内容不继承。
- 完成判定复用投票门禁的可见题组规则：实际显示的题组均须有实质作答；选项触发的隐藏组必须完成，未触发的隐藏组不要求填写；输入题空白文字不算完成。
- 未配置题目的问卷返回 0，不使用门禁为历史空结构保留的 row-coverage 兼容兜底。既有投票门禁行为不变。
- 分母为当前计票流程的 all_voters 人群；高级搜索为其筛选后人群，完成集合与该人群取交集。零分母返回 rate=0。
- 不更改现有问卷作废能力、全局投票者定义、题目选项统计或跨届数据模型。

结果前端通过既有 `/api/v1/questionnaire/structure` 获取 key→title 对应关系，并兼容旧快照的名称；图表形式保持不变。问卷项提示及标签使用后端 rate，而非把所有问卷完成人数相加作为分母。一个人可以完成多份问卷，各问卷完成率可相加超过 100%，扇区大小仍按完成人数展示。
