# 作品批量导入

状态：本地实现、相关检查、管理台构建和独立只读审阅完成，本次阶段提交纳入，未推送或部署；见[执行记录](../plans/2026-11-10-work-bulk-import.md#执行记录)。

## 规则

- 保留现有作品 JSON 导出；批量导入直接接受 works.json，或带 name/type 表头的 CSV。
- 名称、分类均为必填字符串，去除首尾空白；分类沿用 old/new/CD/book/others。
- 按完整名称匹配：不存在则新增，同名同分类跳过，分类变化经预览后更新现有行，保持 ID 和角色/音乐关联。
- 空名称、非法分类、文件内重复名称等错误按记录序号展示；任何错误都不写入整批。
- 只处理文件提供的作品，不删除其他作品；名称变更继续使用已有单条编辑。

## 实施选择

选择独立 POST /api/v1/admin/works/import，与作品管理保持一致；不扩展 voteable 的 category。
请求为 format=auto|json|csv、content、dry_run（默认 true）。响应包含 create/update/unchanged/errors/applied。
错误时仍返回报告且 applied=false；只有无错误的 dry_run=false 才提交事务、刷新现有读取缓存。
更新项包含 previous_type，确认前可查看分类差异。[] 或仅含 CSV 表头为有效空清单，不执行删除。

作品页使用已有 Modal、文件选择和文本预览，显示新增/更新/跳过/错误，再确认导入；修改内容后清除旧预览。
继续使用现有管理员鉴权、数据库表和下载格式，无新依赖、恢复状态机或自动重试。

## 兼容与验证

先导入作品，再导入角色/音乐即可按名称重新建立关联，内部 ID 可变化。
不改变角色/音乐随行创建作品的旧规则，不处理 candidate，不改已有单条作品接口。
相关 HTTP/持久化检查验证预览不写、批量新增/更新/跳过、错误不部分写入、导出再导入及关联保持。
不操作真实数据库，不浏览器交互，不自动提交、推送或部署。回滚代码不需要表结构迁移。
