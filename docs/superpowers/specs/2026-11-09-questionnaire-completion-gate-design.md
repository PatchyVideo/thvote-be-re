# 问卷整体完成闸门设计

日期：2026-11-09。规则及 main/extra 方案已经用户确认；用户补充网站尚未对外发布，本轮退出问卷门禁的旧数据放行兼容。

状态：本地实现及相关验证已完成，退出两处分支并补齐 REST 拒绝响应；纳入本轮提交，未推送或部署。证据见[实施记录](../plans/2026-11-09-questionnaire-completion-gate.md#执行记录)。

## 目标和规则

整套完成＝所有 `required=true` 的问卷完成，并且至少一份 `category=extra`、`required=false` 的问卷完成。当前业务对应 A 必填、B/C/D 至少完成一份，允许多填。A/B/C/D 不是数据库 ID，不按 code、ID 大小或旧 TS 表决定身份。

继续使用现有 main/extra、required 字段。必填集合或 extra 选填集合缺失时不放行；未配置可答题目的问卷不能凭答案行数算完成。单份问卷完成沿用合法性和可见题组评估，结果统计仍分别统计单份问卷，不要求用户先满足整套配额。

## 实施前源码与差额（历史基线）

- 前后端整体政策函数、首页提示已经有本地未提交实现；相关验证已完成，见实施计划的基线记录。本轮不重复重写它们。
- 角色、音乐、组合的 REST 和 GraphQL 提交已经汇入 `SubmitService._require_questionnaire`，再调用 `QuestionnaireService.is_complete`。
- 实际闸门仍先用非空 legacy `raw_paper` 放行；`completion.py` 仍对没有题目的问卷保留 row-coverage 兜底。这两条是本轮需要退出的问卷完成兼容。
- 提名服务不调用同一闸门，本轮不扩大拦截范围。前端路由预判使用本地运行时状态，结构加载失败时现有守卫允许进入页面；服务端仍须独立拒绝未完成用户。

## 调用边界

```text
当前用户＋当前投票年度 → 最新已保存结构化答案
                               ↓
               合法性/可见组 → 单份完成集合
                               ↓
               全部 required ＋ 至少一份 extra
                               ↓
             角色/音乐/组合提交前拒绝或继续写票
```

`completion.meets_completion_policy(questionnaires, completed)` 保持纯函数，`QuestionnaireService.is_complete(vote_id, vote_year, *, answers=None)` 负责编排，`SubmitService._require_questionnaire(vote_id)` 是唯一实际投票闸门。继续传入预读答案，避免重复查询；没有逐题查库、新缓存、完成状态字段或“完成后锁定”机制。

提交问卷继续允许合法但未完成的快照。客户端运行时完成、草稿完成、旧 JSON 有内容均不能代替服务端已存答案。公开 API、错误类型 `QUESTIONNAIRE_NOT_COMPLETED` 和鉴权流程不变，不新增完成查询接口。

## 兼容、发布和回滚

旧 `raw_paper` 记录不再授予投票资格，旧问卷写入/回填接口及数据暂时保留，删除接口或清库不属于本轮。没有题目时直接不计单份完成，删除对应旧行数兼容，不新增迁移器或自动补答。

不新增表、字段、配置项或依赖，不执行真实数据迁移。真实 A/B/C/D 的 required/category 和题目配置尚未核验，发布前应按真实数据库核对；本地夹具只证明规则行为。提交、推送、部署、真实数据修改分别按用户授权执行。

代码回退可恢复原门禁，不会改写或删除用户答案与投票记录；无需数据库回滚。后续配额调整位置见[架构总览](../../architecture/backend-overview.md#问卷整体完成闸门与配置入口)。

## 验收边界

只有 A、只有选填、部分完成、空配置、只有旧 JSON 均不能投票；A 加任意完整 B/C/D 能投票，多填不影响。角色/音乐/组合拒绝时不得产生该类新投票记录。保留既有答案校验、合法部分保存、单份统计测试，不新增浏览器交互或性能验证工程。
