## 方案与边界

使用 `scripts/check_questionnaire.py`，检查函数与命令入口均放在同一文件。相比新增业务模块或管理台检查页面，这个范围满足随时检查及发布前调用；用户明确不增加额外模块。不新增接口、发布状态、数据库字段、依赖或CI工作流，不自动修复数据，也不阻止后台逐项编辑过程中的中间状态。

命令在仓库根目录执行：`python -m scripts.check_questionnaire`。沿用服务配置选定数据库，仅查询四张定义表，不读用户答案、不初始化表、不清缓存。发布人员在确认目标数据库配置后调用同一命令；本轮不改部署设施。

## 检查范围

- 读取全部 questionnaire/group/question/option 行，先查 ID 重复、父节点缺失，不能复用会过滤孤立节点的普通结构加载器。
- 问卷 key 非空且唯一，category 为 main/extra；至少存在必填及 extra 非必填问卷，沿用整体政策的成员定义，不硬编码 A/B/C/D 的真实 ID 或数量。
- 每份问卷有题组；题组 order 为正整数、同问卷内唯一，首组 order=1 且仅一道题、默认可见；每组题目非空。
- 题型为 Single/Multiple/Input；选择题有选项，Input 不配置选项且 max_input_len 为正整数；选项内容非空，option_group 为非负整数。
- related/mutex 为整数 ID 列表，目标存在且同问卷；related 严格指向后续题组，按 order 比较，不能按 ID 或 code 推断；mutex 不能指向自身，允许单向声明。Multiple 的不同选项组是正常配置。
- 复用 normalize_code 检查非空 code 格式（题5位、选项7位），同类 code 唯一；缺失 code 仅警告，不提高现有编码要求。

只检查上述静态约束，不枚举答案组合，不证明所有分支可达或一定存在完整解。首组顺序及 Input 长度检查是为匹配现有运行时作出的局部实现选择。

## 输出与失败

一次返回全部发现的问题，每条含 error/warning、稳定错误码、对象类型与真实ID、中文说明。最后打印错误/警告数量。退出码：0=无错误（可以有警告），1=定义错误，2=配置、连接、查询或执行失败。失败只显示异常类别和排查提示，不输出连接串、密码或原始异常详情。
