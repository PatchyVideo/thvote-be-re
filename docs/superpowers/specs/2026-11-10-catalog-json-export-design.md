# 基础资料 JSON 导出

2026-11-10，用户已确认采用管理台下载按钮，先写计划后直接实施。
状态：本地实现、相关测试、管理台构建和独立只读审阅完成，未部署；见[执行记录](../plans/2026-11-10-catalog-json-export.md#执行记录)。

## 已确认范围

- 导出作品、角色、音乐的完整业务清单，JSON 为扁平对象数组，中文可读。
- 字段适配现有业务导入；work 表示首次登场作品名称，附 work_type；资源保留 URL。
- 保留名称、日文名、类型、首次登场日期、别名、旧 ID 和资源信息；不导出数据库自增 ID、创建时间或 candidate。
- 作品独立导出 name/type，包含没有关联角色或音乐的作品。
- 下载全量数据，不受页面搜索、分页或届次影响；空清单为 []。

## 方案与取舍

已选择管理台按钮及管理员下载接口。命令行方案虽更少前端改动，但日常维护不如页面下载方便。
新增 GET /api/v1/admin/export/catalog?category=work|character|music，沿用现有管理员鉴权和下载流程。
返回 works.json、characters.json 或 music.json；后端直接查询当前数据库，不读取旧快照。
读取与字段映射集中在小型导出 service，路由只负责响应，页面只负责下载操作。

## 边界

不新增依赖、表或数据库字段，不执行云端导出、真实数据写入、发布或部署。
不改 candidate；不新增作品批量导入。works.json 目前可供现有单条作品接口维护，批量恢复入口后续处理。
角色/音乐可通过现有业务导入重新建立事实，内部 ID 不保证保持；null/空白沿用现有导入的不更新语义。
文件归档的是库内现有资料，不额外核验每一项事实，也不下载图片或音频本体。
回滚移除新增接口、service 和按钮即可，没有数据回滚操作。
