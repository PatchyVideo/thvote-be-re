# 问卷定义来源统一设计

状态：2026-11-09 实现及验证完成，已提交后端f12e3ce、前端4fda4ef，未推送或部署。验证及实际边界见配套实施计划，后续规则及剩余事项见[当前问卷清单](../../migration/questionnaire-audit-2026-11-09.md)。

## 实施前现状与目标（历史基线）

后台已管理四层问卷定义，填写端已读取 `GET /api/v1/questionnaire/structure`。结果端的查询清单、题干、题型、选项和高级搜索仍依赖旧静态 TS 题库。目标是让填写和结果消费同一份后端定义，并补齐管理台 code 维护。

源码与需求证据见[审查记录](../../migration/questionnaire-audit-2026-11-09.md)。本设计不代表已核验线上题库或部署。

## 方案与取舍

采用现有角色方案：共享请求与类型；填写端保持自己的响应式状态和草稿，结果端保持自己的内存索引。两个独立前端应用分别请求各自 API 地址，刷新网页后重新请求，同次运行复用成功响应并共用进行中的请求。

继续使用数据库 id 关联答案、related 和 mutex；题目/选项 code 用于统计查询、DSL、结果链接。全部结果寻址改成 id 会牵涉快照键、语法、配置与链接，不在本次范围。也不建立统一管理填写、统计与草稿的新框架。

## 数据契约与职责

- 复用 `/questionnaire/structure`，不新增公开接口或数据库字段。它返回 questionnaires、层级、真实 id、题干、类型、规则以及可空 code；共享类型补齐已存在的 code/order。
- `shared/api/questionnaire.ts` 提供请求、基本响应检查与纯索引构建。请求函数接收完整 URL，不硬编码 vote/result 的代理前缀，也不维护跨应用全局缓存。
- 填写端 `questionnaireStateV2.ts` 管结构加载状态、草稿、解析、回填、提交。后端结构替代 sessionStorage 默认来源；localStorage 答案草稿保留，按当前定义归一化。
- 结果端 `lib/Questionnaire.ts` 管结构加载和内存复用，使用共享索引；题目 code 对应统计 `q<code>`，选项 code 对应结果 aid。不得从编码截取层级，不得用数据库 id 冒充缺失 code。
- 各页加载失败显示错误与手动重试；不读取旧静态题库充当成功响应。重试复用现有页面做法，不增加自动重试队列或恢复状态机。

## 结果消费

覆盖通用 Questionnaire 组件（全局、角色、音乐、组合详情共用）、文本答案详情和 AdvancedSearch。结构就绪后生成查询清单；查询条件变化继续沿用现有 DSL 和目标人群交集。

以定义为完整题目清单，按 code 关联统计；已计算快照内缺少某题时展示零回答，缺少选项计数时补零。整届 RESULT_NOT_COMPUTED、请求失败不能转成零回答。无 code 的题目仍可填写，结果界面明确说明暂不可查询统计；高级搜索不提供无法生成 DSL 的题/选项。

排序保留当前结果按题目 code 数值升序的行为，以遵循 PRD 编号排序；填写顺序沿用后端 order。此次不引入问卷级 code，不从自增 questionnaire.id 推断需求的二位业务编号。

保留既有 q11031 地图、q11011 饼图与 q11011 趋势代理绑定；不自动选择“第一题”替代。将其保留为已知展示规则，不称为正式题库数据。以后迁移到后端展示配置时单独确认字段与管理方式。

首页名称和说明直接读取后端 title/introduction；现有按 key 的图片装饰可暂保留，未知 key 使用页面默认图或无图布局。本次不新增图片列；分类提示与门禁规则差异留在既有待办中。

## code 维护建议

后台题目/选项表单显示只读 id 和可编辑 code，提示其统计、链接用途和缺失影响。code 由编辑人员明确填写，不按主键或排序自动生成。

- 非空题码为 5 位 ASCII 数字，选项码为 7 位 ASCII 数字，保存为字符串。空白统一为 null，保持历史空 code 的兼容；不引入“发布/草稿”新状态。
- 非空 code 在各自题目表/选项表内检查重复，更新排除自身。管理创建、更新、整树导入使用同一规则，导入先校验再删除原结构。
- 不新增 DB 唯一约束、锁或并发协议；管理写入为低频，应用层重复检查满足本轮需求。历史重复记录不自动清理。
- 本轮不重写层级编码、不强制修改现有 code、不因排序变化重新编号；选项前缀与题码、题码与分类是否一致，属于更完整编码治理，暂不追加级联改码机制。
- 正式统计所需 code 缺失、重复或含义改变仍需管理人员核对。修改 code 后现有结果快照不会自动改写；历史答案依赖定义，删除重建不能靠 code 自动恢复。

## 范围边界

不改问卷完成产品规则、legacy 门禁、作答规则校验、管理作废覆盖、跨届版本模型、统计算法或快照生命周期。不全库回填，不真实导入或重算，不新增依赖、CI、发布流程或浏览器自动交互。

保留无关未提交改动。当前两个工作区都有其他任务改动；执行前确定隔离位置，不在合作者分支修改。未经明确要求不 commit、push、部署或操作真实数据。

## 验收与回滚

后端编辑的题干、选项在两个前端重新加载后都生效；使用 id 与 code 无关的测试数据验证映射。现有筛选链接保持语法，全部四类详情人群条件保留。新增永久测试只针对映射、加载复用、编码校验这些关键行为，复用当前 node:test/tsx 和 pytest，不新增测试框架。

前端与管理台构建、相关后端检查通过后停止扩展验证；页面验证最多截图。没有真实账号或线上题库验证时如实说明。

不改变存储模型，产品代码可成套回滚；已人工修改的 code 不会随代码回滚，届时人工核对恢复。结果重算、真实回填和发布需另行授权。
