# 问卷答案合法性与完成度设计

日期：2026-11-09。状态：实现与相关验证完成，后端已提交e9dc072，未推送或部署；实际验证与边界见配套实施计划。本阶段实施基线为后端f12e3ce、前端4fda4ef。

> 后续规则变更：本设计保留第二阶段范围及当时的 required-only 整体判断。2026-11-09 后续已接入“全部必填＋至少一份 extra 选填”，当前规则与实际门禁范围见[架构总览](../../architecture/backend-overview.md#问卷整体完成闸门与配置入口)；下文单份作答规则仍适用。

## 目标与范围

后端已有 ID/归属/文本长度校验和完成判断，但单选数量、题型对应答案形式、选项组互斥、mutex 和实际分支校验不完整。补齐这些规则，防止正常 UI 无法产生的答案写入，同时让门禁与完成率采用同一份作答语义。

提交内容仍为凭证和全量扁平答案行，包含其他未答问卷和隐藏题组；不能要求所有行必答。合法未完成可保存，非法答案拒绝且不落库，不在服务端替用户修改、删除或选择答案。

不改 required 完成产品规则、legacy raw_paper 门禁、V2 管理作废、code 维护、跨届题库版本、题目回答统计/趋势算法。不新增独立校验接口、完成字段、数据库表/列、缓存、依赖、自动重试或 CI。

## 方案与边界

采用现有模块的局部扩展：StructureIndex → rules → validation → completion → service。保留 validation/completion 已有调用入口；新增 rules.py 只负责纯计算，不访问 DB/Redis。相比把逻辑继续堆在大函数中，此方案使分支规则有明确出处；通用规则引擎和单独的“先校验后提交”双请求都没有必要。

- structure_index.py：按真实 id 索引定义、父子归属、选项和排序。一次请求/统计批次建立一次，不能依赖 code 或按 id 大小推断前后。
- rules.py：计算可见题组、允许的当前题、有效已答组和冲突，承载内部结果类型及纯函数。输入答案不可变更。
- validation.py：首先检查提交结构和引用，再调用 rules；给出内部可检查结果，并由兼容包装函数转为现有 ValidationError。
- completion.py：根据同一份评估计算逐问卷完成集合、required 整体判断，不再维护第二套可见性传播。
- service.py：加载定义、建索引、校验、写入。GraphQL resolver 继续负责认证和错误映射。

## 合法答案规则

1. 保留现有整数 ID、归属、重复行/选项、文本类型和长度检查。None/缺省选项可按既有约定视为空，不能用 `or []` 掩盖 false、0 等错误类型。
2. Single 可为零或一个选项，零项表示未答；多项非法。Single/Multiple 不接受非空 input，Input 不接受选项。
3. Multiple 已选项必须属于同一 optionGroup；同一题组内和跨题的显式 mutex 都按声明的方向检查，存在 A→B 时不能同时选择 A/B，不推导额外反向规则。
4. 可见题组的 activeQuestionId 若非空，必须是当前允许分支。为空且无答案可作为未答保存；缺少的答案行不表示完成。
5. 隐藏题组只能为空状态；其非空当前题、选项或文本均拒绝。隐藏分支的答案不能用来解锁它自己或传播到其他组。
6. related 只在同一问卷内按真实题目引用解析。首组/order==1 的现有默认题语义保持；默认隐藏用 hiddenByDefault，不恢复第0题或 ID 尾数约定。
7. 多个可见来源命中同组时，延续前端行为：提交当前题若在命中集合中可保留，否则使用稳定顺序中的首个目标作为应出现题；无触发时使用默认题或隐藏。不新增业务优先级。
8. Input 以 strip 后非空为已答；选择题须有至少一个合法选项为已答。输入长度沿用 maxInputLen 默认1000；不引入 emoji/字符计数口径调整。

## 分支计算与配置边界

从默认可见组开始，只传播已确认可见且分支匹配的答案；重复推进至稳定。采用与前端现有解析器相同的按组数限制（最多 max(1, 4×组数) 轮），不使用无界循环或新增拓扑/队列框架。先进行局部题型/归属检查，冲突答案不能作为可信完成状态。

遇到循环导致不收敛，返回明确的 QUESTIONNAIRE_CONFIGURATION_ERROR，不保存、不按空问卷放行；文案提示联系管理员，不伪装用户选错。此轮不扩大成完整管理端配置检查，也不假定线上已存在逆向或循环关联。若实施发现合法前端输出与这套语义冲突，先定位并报告真实差异，不自动调整产品规则或吞错。

## 完成判定和历史读取

- 单份已配置问卷：至少一个可见组，所有可见组均有合法实质作答，且该问卷没有规则错误。已触发的隐藏组须答，未触发的不要求。
- 某份问卷有非法答案时该份不计完成；其他合法问卷仍分别计算。整体继续按 required 完成集合判断。新提交任何非法行都拒绝整个新批次。
- 现有历史读取对已不存在组的孤立答案忽略，以及未配置题库的门禁 row-coverage 兜底，保留在 completion 兼容包装中；提交入口仍严格拒绝未知 ID。结果统计继续排除未配置问卷，不把兜底用于完成率。
- 老数据中已知题组的单选多项、错误分支或互斥冲突不再算该份完成；不清理、不改写旧批次，不使整批统计因某位用户非法答案而异常退出。题目回答计数管道本轮不同时重做。

## 返回契约

内部 AnswerIssue 含稳定原因 code、questionnaire/group/question id（可空）及安全文案；只向当前提交返回首个可定位错误，不实现错误列表 UI。

公开接口保持 submitPaperV2:Boolean、getPaperV2 和答案字段形状不变；用户作答错误沿用 error_kind=INVALID_PAPER_ANSWER，以 human_readable_message 指出问卷/题组和原因，失败不写库。配置不收敛使用独立错误种类，交给现有错误映射。内部定位信息不作为新 GraphQL 字段暴露，详细结构化完成响应留待后续需求。

## 性能与验证

结构仍批量读取四层，纯规则不新增 SQL。校验与完成共用一个索引和评估；统计批次沿用外层单次索引。投票门禁把预先读取的答案传给 is_complete，取消当前重复读取。保留现有 HTTP 结构缓存边界，不默认扩成进程缓存或 Redis 编译缓存。

单轮计算以 G 个组、A 个选中选项、E 条生效关联/互斥边为主，利用字典/集合接近 O(G+A+E)；总成本还乘实际迭代轮数，不能宣称整体永远线性。性能只做一次临时合成样本测量，分别记录索引构建和单用户规则计算，不设无依据毫秒门槛，也不建立性能 CI。

复用真实生产函数的单元测试与现有 GraphQL/持久化夹具。仅在合适一层覆盖规则组合，集成层覆盖非法不写库和合法未完成可保存。无浏览器交互、真实库核验或自动重算。

回滚代码可恢复原校验；不会自动恢复/删除期间提交的答案。真实回填、统计重算和部署另行授权。现有未提交改动保留，不在本轮计划编写时提交或改产品代码。
