# 候选导入与新版答卷管理

状态：用户已确认（2026-11-10），按配套计划本地实施；不执行云端迁移或部署。

## 当前问题

- 候选表已只维护届次、投票对象引用和排序。候选导入预览仍显示旧版名称、日文名、出处等输入字段，实际返回的有效行只有 `voteable_id`、`sort_order`，导致预览空白。
- 候选页面默认届次使用公历年份，导入又回退到硬编码 2026；应使用服务端配置的当前届次。
- 修改导入内容后，旧预览没有失效。当前服务仅检查 `voteable_id` 非空，未在预览阶段验证整数、真实对象和排序；有错误行时仍可写入其余行。
- 候选列表 DAO 已返回 `voteable_id`，管理接口转换时丢弃了它，排序也未返回，编辑窗口无法正确回填。
- 旧监控的 `paper` 类别读取 `raw_paper`。新版数据在 `paper_answer`，按账号、届次、attempt 保存整次答案快照，尚无管理查询和作废标记。

## 方案与取舍

推荐保留现有 Vue 管理台与导入接口，修正候选导入契约；为新版答卷提供独立列表和详情，复用现有题库与完成度判断。

候选导入继续使用文件或粘贴 CSV/JSON，增加可读预览即可。新增完整的对象勾选器可以减少填写 ID，但超出本次导入页修正范围，暂不建设。

答卷只读查询不需要变更表结构；若同时支持作废、恢复，推荐在现有 `paper_answer` 增加 `invalidated` 布尔字段，整批统一更新。独立的提交头表可以集中保存批次信息，但目前没有必要为此重建存储关系。

## 一、候选导入

1. 明确说明操作含义：把已有角色或音乐加入指定届次；基础资料仍在投票对象页面维护。
2. 明确区分候选记录 ID 和投票对象 ID。导入字段为必填 `voteable_id`、可选 `sort_order`；提供 CSV/JSON 示例和本地文件读取。
3. 届次从服务端配置初始化，窗口单独保存届次和类别，避免修改列表筛选时改变待导入目标。
4. 预览校验 ID 为正整数、引用对象存在、排序为合法整数，同一文件重复引用报错。使用当前请求连接的数据库查询对象，不使用本地静态映射。
5. 预览展示名称、作品、投票对象 ID、排序及新增/更新/不变，错误显示行号和原因。文件、内容、类别、届次或格式改变后清除旧预览。
6. 推荐与作品导入保持一致：存在错误则整批不写入；修正后重新预览、确认。确认请求重新校验，仍按届次和对象唯一关系新增或更新，不删除文件外的候选。
7. 候选列表及编辑补齐 `voteable_id`、`sort_order`；去掉已经没有实际数据来源的候选合并入口。

接口继续使用 `POST /api/v1/admin/candidates/import`，保留原有输入及响应字段，扩展预览元数据和操作数量。候选列表响应新增引用 ID 和排序。错误时禁止部分写入属于明确的行为变化，需记录接口文档及 changelog。

## 二、新版答卷管理

管理台新增“答卷管理”，与“问卷配置”分开。

- 列表按账号、届次汇总最新提交，支持届次、账号、有效/作废筛选；显示提交时间、批次、各问卷完成情况和整体投票资格。
- 详情按问卷、题组展示题目、选项文本和自由输入，可切换历史提交批次。题库中已不存在的引用保留 ID 和原始值，并提示无法解析，不猜测题意。
- 同时展示填写完成情况和批次有效性，避免把已作废但填写齐全的快照标成可投票。
- 复用现有完成规则：所有必填问卷完成，并至少完成一份额外问卷；不重新实现一套前端判定。
- V2 未采集 IP、设备和耗时，本次不补造这些信息，也不扩展采集模型。

建议新增管理接口：

- `GET /api/v1/admin/questionnaire-submissions`：分页查询最新提交。
- `GET /api/v1/admin/questionnaire-submissions/{vote_year}/{vote_id}`：查看该账号该届次的提交批次及可读答案。
- `PATCH /api/v1/admin/questionnaire-submissions/{vote_year}/{vote_id}/{attempt}`：整批设置作废或恢复，输入仅为 `invalidated`。

服务和 DAO 放在现有 questionnaire 模块，继续使用现有管理鉴权；不把 V2 强行塞入依赖 raw 表行号和 IP 字段的通用监控查询。

### 推荐作废口径（须确认）

- 作废单位为一次整套提交快照，即账号、届次、attempt；不逐题、逐问卷作废。
- 最新批次作废后，服务端完成资格立即不通过，不自动回退到旧批次；恢复最新批次后重新按原有规则判断。操作历史批次不会将其提升为当前批次。
- 最新批次作废时，该账号该届次问卷数据退出当前统计、完成度和趋势计算；最新批次有效时，历史趋势跳过已作废批次。高级筛选使用同一数据口径。
- 已生成的普通结果快照通过现有手动重新计票更新，管理台操作后提示需要重新计票。本次不新增自动任务。
- 不连带作废已提交的角色、音乐、CP 票，也不封禁账号。用户仍可修改后重新提交，新批次默认有效。
- 普通答卷回填仍允许读取最新原始内容以便修改；完成资格查询必须另外排除作废快照，不能因可回填就视为有效。浏览器原有草稿不自动清除。

## 三、raw_paper 退出边界

本阶段把管理台答卷浏览切换到 V2，移除投票浏览器、账号详情等活跃管理入口对旧 paper 数据的展示，避免两个页面给出相互矛盾的状态。

旧提交接口、同步、导出及物理删表仍按后续 raw_paper 退出任务处理，不在本阶段顺带删除登录接口或执行云端迁移。

## 迁移、回退与验证

- 若确认作废功能，增加 Alembic 迁移，现有行 `invalidated=false`，不修改原答案和 attempt；实际云端执行须另有授权。降级仅移除新字段，丢失作废标记，原答案仍在。
- 本地实现按候选导入、答卷查询、作废口径三个步骤推进，每步保持模块边界；文档和 changelog 同步更新。
- 使用已有候选导入和问卷测试；仅针对关键新增行为和实际缺口补简短用例，集中运行相关检查、管理台构建和差异检查。
- 不执行浏览器自动点击流程，不提交、推送、部署或写云端业务数据。
